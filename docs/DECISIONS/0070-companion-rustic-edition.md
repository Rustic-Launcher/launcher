# 0070. The in-game companion: a trait mod plus platform player hooks, linked into the prebuilt Rustic edition

- Status: accepted (content, 2026-11-10). Implements spec ADR 0006 (user decisions of 2026-11-10: prebuilt by our CI
  and downloaded by the launcher, never built on the player's machine; Horizon's own cosmetics stay on beside
  Rustic's).

## Context

Horizon has no WebAssembly mods on main: code mods are native. Two code paths reach the game (Horizon at a84f637d,
`NATIVE_HOOKS_API` 415):

1. **Trait mods** (`horizon_client::mod_api::Hooks`, generated from `native-hooks.json` and the pending fragments).
   Client hooks used: `client_tick_post`, `key`, `hud` (`HudBatch`, `Corners`), the mod's own screen
   (`Host::mod_screen_open/mod_screen_close/mod_screen`, `screen_render_post`, `screen_mouse_button_pressed_pre`,
   `screen_key_pressed_pre`, `screen_closing`), `client_disconnecting`; helpers `fill`, `text`, `quad`,
   `text_width`, `add_toast`, `client_state`, `config_dir`.
2. **Platform hooks** (`horizon_hooks::Hooks`): `frame` (put 64x64 RGBA sprites in the atlas, `SpriteStore`), `tick`
   (player models in view, `set_body_pose` for emotes), `player_layers` (draw `Mesh`es on bones with a `Look`,
   `particles`), `name_decoration` (badge and line). Registered by an executable's `main` before the game seals the
   list. A `.hnmod` built by Horizon's launcher cannot reach them: its `main` is generated by that launcher, and a
   bundle may not depend on `horizon-hooks` by path (`horizon/launcher/src/native_mods/api.rs` refuses any path
   dependency but the bundle's own crates). `mod_api`'s `mob_layer`/`player_submit` draw only with atlas sprites
   *named* by resource packs (`draw_quad`, `draw_cube`), not the downloaded textures cosmetics need.

## Decision

- `launcher/client-mod/rustic-companion` is its own Cargo workspace (Horizon's `[patch.crates-io]` with adjusted
  paths, `Cargo.lock` seeded from Horizon's so the game's crates keep Horizon's exact versions), excluded from the
  launcher workspace, with three crates:
  - `core` (`rusticmc-companion-core`): no Horizon type: cloud protocol, worn cache, bundle store (SHA-256 then the
    format's validation), social state and news, overlay and wheel geometry, notifications, deterministic trails.
    Tested on its own.
  - `mod` (`rusticmc-companion`): `hooks()` (the trait mod) and `register_platform_hooks()` (the player hooks).
  - `edition` (`rustic-edition`, binary `rustic-client`): its `main` registers Play with Friends
    (`horizon_friends::game::HOOKS`, the one Horizon part ADR 0006 keeps), the companion's player hooks, names the mod
    (`mod_api::name_mods`) and calls `horizon_client::entry::main_with(vec![rusticmc_companion::hooks()])`, with
    Horizon's allocator and mod-API-level mark (`horizon_game`) and an 8 MB main-thread stack on Windows (as
    Horizon's executables). Horizon's in-engine cosmetics (feature `horizon-extras`, default) stay on.
- Shipped as ADR 0006 says: Rustic's CI builds `rustic-client` per OS from a pinned Horizon commit, packs it with the
  Horizon release folder of the same commit, signs (`SHA256SUMS` with our Ed25519 key, Authenticode, notarisation);
  the launcher downloads and verifies it. Sketch: `launcher/client-mod/rustic-companion/ci/rustic-edition.yml`.
- Rejected: a `.hnmod` (`horizon-mixin.toml` with an `[api]` crate, per cargo-horizon-mod's native template) built by
  Horizon's launcher. It covers the trait-mod half only (no player drawing), needs Rust and a 2 GB build on the
  player's machine, and Horizon's Content API says other launchers don't offer native mods.
- The companion never blocks the render thread: one network thread of its own; hooks read caches under one short
  mutex, never held across a `Host` call that may run hooks; every hook body runs under `catch_unwind` (a panic in a
  hook would end the game).

## Honest limits at the pin

- Cosmetics draw through `horizon_hooks` only, hence the edition executable (no dynamic textures in `mod_api`).
- No hook connects to a server: accepting an invite asks the launcher (cloud) to restart the game into it.
- The overlay is the mod's own screen: Horizon frees the mouse and closes it on Escape; a gamepad closes but can't
  click it.
- `name_decoration`: the first hook that answers wins; Rustic answers only for players with a Rustic name-tag style,
  so Horizon's mark and style show otherwise (RISKS R-09). Rustic's sprites use ids under a high prefix so they never
  share an atlas name (`hooks/<hex>`) with Horizon's.
- Not drawn yet: other players' emote props, the companion's follow lag (it sits at its anchor), the first-person
  companion.
- Single player names the player by an offline profile: no Rustic cosmetics there (as Horizon's).
  (Since ADR 0146 an offline launch carries the owner's official name and UUID.)
- Hook APIs are experimental: each Horizon bump is a CI compile and a QA pass.

## Verification (2026-11-10, Horizon a84f637d)

`cargo check` and `cargo clippy --workspace --all-targets -- -D warnings` of the companion workspace against the real
`horizon_client::mod_api` and `horizon_hooks` (`CARGO_TARGET_DIR=<Rustic-MC>/horizon/target`), `cargo test -p
rusticmc-companion-core` (18 tests), and a debug `cargo build -p rustic-edition`: `rustic-client.exe` (165 MB) links
and answers `--launch-api` (hooks 415, resource pack format 97.1, data pack 121.0). Not yet run in a world: needs
prepared game files and a signed-in session (manual QA).
