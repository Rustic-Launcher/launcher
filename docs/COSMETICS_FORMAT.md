# Rustic cosmetic format (`cosmetic.json`, format 1)

Owner: content. Code: `launcher/packages/cosmetics-format` (Rust crate `rusticmc-cosmetics-format`); JSON Schema
for the TypeScript side: `launcher/packages/cosmetics-format/schema/cosmetic.schema.json` (regenerated by its test
with `UPDATE_SCHEMA=1`, also printed by `rustic-cdn-pipeline schema`). Pipeline: `launcher/services/cdn-pipeline`.
Decisions: ADR 0060 (format), 0061 (budgets and rules), 0062 (pipeline and CDN layout).

Rustic cosmetics are **purely visual**: drawn by Rustic-edition clients only, from Rustic Cloud's answers; nothing is
sent to game servers, nothing collides, nothing changes gameplay. **No capes** (or anything that looks or acts like
one: capes are Mojang's), **no random content** (no loot boxes, no random draws, no randomness in rendering: every
motion is a function of time and distance walked).

## Authoring

Model in **Blockbench** as a Java "Modded Entity" model (boxes with box UV), the same workflow as Horizon's and
vanilla's `ModelPart`s, and write the JSON below (a Blockbench export plug-in is a TODO for the frontend owner).
Free-form meshes may come from Blockbench's **glTF 2.0** export (`.glb`, or `.gltf` with embedded buffers) as a
`mesh` model; those draw in Rustic's companion but have no Horizon form.

A **package** is a folder (or a `.zip`) holding `cosmetic.json` and the files it names (the PNG texture, the glTF
file). A **bundle** is the self-contained form the CDN serves: the texture embedded as base64, a mesh's triangles
inline, nothing else to resolve.

## Space

Model pixels (1/16 block) in the player model's space, **y pointing down**. A part's `pivot` is its `PartPose`
offset and its boxes are relative to it; rotations are degrees applied Z, then Y, then X (`rotationZYX`). Front of
the player is -z, its back +z; +x is the player's left.

## The file

```json
{
  "format": 1,
  "id": "top_hat",
  "version": "1.2.0",
  "name": "Top Hat",
  "description": "Optional.",
  "authors": ["Rustic"],
  "category": "head",
  "attachment": { "point": "head", "offset": [0, -8, 0], "rotation": [0, 0, 0], "scale": 1 },
  "texture": { "path": "textures/top_hat.png" },
  "model": { "kind": "cubes", "parts": [
    { "name": "brim", "cubes": [{ "origin": [-5, -1, -5], "size": [10, 1, 10], "uv": [0, 0], "inflate": 0, "mirror": false }] },
    { "name": "crown", "pivot": [0, -1, 0], "rotation": [0, 0, 0],
      "cubes": [{ "origin": [-3, -6, -3], "size": [6, 6, 6], "uv": [0, 11] }], "children": [] }
  ] },
  "loops": [{ "part": "crown", "motion": "bob", "axis": "y", "amplitude": 0.5, "period": 60, "phase": 0 }]
}
```

| Field | Rule |
|---|---|
| `format` | `1`. A reader refuses a higher number. |
| `id` | `[a-z0-9_]{1,64}`. Also the Horizon item id when converted. |
| `version` | `MAJOR.MINOR.PATCH`. A published version never changes: the pipeline refuses the same version with other bytes. |
| `name` | 1 to 64 characters (English; translations live in the catalogue). |
| `description`, `authors` | Optional. |
| `category` | One of the table below. A player wears at most one per category (and plays emotes). |
| `attachment` | Where it sits: required for `head`, `back`, `top`, `shoulder_companion`; optional for an `emote`'s props; refused otherwise. |
| `texture` | `{ "path": "<file in the package>" }` or `{ "png": "<base64>" }`, not both. |
| `model` | `{ "kind": "cubes", "parts": [...] }` or `{ "kind": "mesh", "source": "x.glb" }`. Absent for `trail` and `nametag`. |
| `loops` | Looping motions of named parts (below). |
| `emote`, `companion`, `trail`, `aura`, `nametag` | The block of the category of that name; refused on any other category. |

Unknown fields are refused everywhere: a typo is an error, never a silently ignored setting.

### Categories

| Category | Horizon slot | Needs | Notes |
|---|---|---|---|
| `head` | `head` | attachment, model | hidden under a helmet |
| `back` | `back` | attachment, model | hidden under an elytra or cape; **never cape-like** |
| `top` | `torso` | attachment, model | over the body; top-level parts may ride the arms (`"bone"`); hidden under a chestplate |
| `shoulder_companion` | `shoulder` | attachment, model | a small pet on a shoulder |
| `companion` | `companion` | model, `companion` | floats beside the player, on no bone |
| `trail` | `trail` | texture (a row of sprites), `trail` | particles by distance walked, no model |
| `aura` | `aura` | model, `aura` | see-through model at the feet |
| `emote` | `emote` | `emote` (props optional) | played from the emote wheel, never worn |
| `nametag` | `name_tag` | square texture <= 16x16, `nametag` | a badge after the name and a line under it |

There is no cape category, on purpose.

### Attachment points (the player skeleton)

| Point | Bone | Base offset (px) |
|---|---|---|
| `head` | head | 0, 0, 0 (the neck) |
| `body` | body | 0, 0, 0 (the neck) |
| `back` | body | 0, 0, 2 (top of the back) |
| `left_shoulder` | body | 6, 0, 0 |
| `right_shoulder` | body | -6, 0, 0 |
| `left_arm`, `right_arm`, `left_leg`, `right_leg` | that bone | 0, 0, 0 (its pivot) |

The cosmetic sits at the bone's matrix, then `base + offset`, `rotation` (degrees, ZYX) and a uniform `scale` in
(0, 2]. The name tag has no attachment: it is drawn by the name.

### Boxes

`origin` and `size` in pixels, box UV from `uv` (the unfolded box spans `2(d + w)` by `d + h` texels and must stay
inside the texture), `inflate` 0 to 4 grows the box over the same texels, `mirror` mirrors it in x. Part names are
unique and never start with `cosmetic`. Only a top-level part may name its own `bone` (a shirt's sleeves).

### Meshes (glTF 2.0)

`"model": { "kind": "mesh", "source": "fin.glb", "units_to_pixels": 16 }`: every node with a mesh becomes a group
(named after the node), its triangles in pixels (y flipped to point down), UVs from `TEXCOORD_0`. Only triangle
primitives; buffers embedded (`.glb` or `data:` URIs). Groups are named and may be animated like parts. The bundle
carries `groups[].triangles` inline and drops `source`.

### Motion: loops

`{ "part", "motion": "swing" | "bob" | "spin", "axis": "x" | "y" | "z", "amplitude", "period", "phase" }`: a sine of
`period` ticks (4 to 1200) started `phase` periods in, on top of the part's rest pose. `swing` turns up to 45 degrees,
`bob` moves up to 4 pixels, `spin` turns once per period. A function of the model's age only.

### Emotes

`"emote": { "length": 40, "loop": false, "blend": 4, "tracks": [ { "part": "right_arm", "keys": [ { "t": 0 },
{ "t": 8, "rotation": [0, 0, 150], "ease": "smooth" } ] } ] }`. Tracks move a bone (`head`, `body`, `right_arm`,
`left_arm`, `right_leg`, `left_leg`), `root` (the whole body) or a prop part. `length` 4 to 200 ticks, `blend` at most
half the length, at most 16 tracks, 32 keys a track and 192 in all, keys going forward in time, turns up to 360
degrees (root 720), moves up to 8 pixels (root 16), only a prop's key scales (0 to 2). Eases: `smooth`
(Catmull-Rom), `linear`, `in_out`, `step`.

### Companions, trails, auras, name tags

- `"companion": { "anchor": [-14, -6, 8], "lag": 8, "look": "head", "glow": false }`: anchor at most 28 px from the
  neck and at least 11 + its size from the head's centre; lag 1 to 40 ticks; the companion itself within 8 px.
- `"trail": { "sprites": 4, "rate": 2, "lifetime": 30, "size": [1.5, 3], "gravity": 0.01, "drift": 1.5, "spin": 8,
  "from": "feet", "fade": true, "glow": false }`: the texture is a row of `sprites` (1 to 8) square sprites of at most
  16 texels; rate at most 4 per block, lifetime at most 40 ticks, size at most 4 px, gravity within 0.04, drift 0 to
  4, spin 0 to 20. Particles come from distance walked only and each one's variation from its index.
- `"aura": { "at": "feet" | "body", "alpha": 0.5, "glow": true }`: alpha at most 0.6 (feet) or 0.35 (body); within
  14 px of the feet's middle sideways, 6 px up at the feet or 30 around the body, 1 below.
- `"nametag": { "line": "#a98fff" }` with a square badge texture of at most 16x16.

## Budgets

| Budget | Value |
|---|---|
| Box model vertices | 512 (4 per face, 21 boxes) |
| Mesh triangles | 512 |
| Parts (or mesh groups) | 16 |
| Texture | power-of-two sides, at most 64x64 (one skin-atlas slot) |
| PNG file | 64 KiB |
| Bundle | 256 KiB |
| Reach | 24 px from the bone's pivot, animations included (sampled over every loop and the emote) |

The box-model numbers are Horizon's own (`horizon_cosmetics::Item::parse`), so a box cosmetic that validates here
converts into an item Horizon accepts.

## Validation API

`rusticmc_cosmetics_format::validate(&cosmetic, texture, png_bytes) -> Report` (or `Package::validate()`):
every problem at once, each with a `code` (`format`, `id`, `version`, `name`, `category`, `attachment`, `texture`,
`model`, `budget`, `reach`, `animation`, `emote`, `fx`, `nametag`, `cape_like`), a place (`model.parts[1].cubes[0]`)
and a message; warnings (a fully transparent texture); and stats (vertices, triangles, parts, texture size, reach)
for the creator UI's budget panel. `report_schema()` is its JSON Schema.

Cape rule: refused by name (`cape`, `cloak`, `mantle`, `elytra` in the id or name) and by shape (a `back` item that
is a flat panel at most 2 px deep, at least 6 wide, hanging 10 px or more below the neck).

## Conversion with Horizon's format

`horizon::to_horizon` / `from_horizon` (`rusticmc_cosmetics_format::horizon`), against Horizon's item JSON
(`horizon/crates/horizon-cosmetics/src/item.rs`, `docs/cosmetics.md`):

- **Horizon -> Rustic -> Horizon is lossless**: the same item field for field, once Horizon's defaults are spelled
  one way (`normalized`: a head bone and a neutral attachment left out). Tested on Horizon's documented example.
- **Rustic -> Horizon** keeps everything Horizon draws: parts, boxes, loops (`animations`), the emote, companion,
  trail, aura blocks (same shapes), the name tag (`tag`), the texture embedded. It reports what it drops: version,
  name, description, authors, and a named attachment point (folded into the bone and offset: `back` becomes body +
  (0, 0, 2) + offset).
- **Not representable**: mesh models (Horizon items are boxes only), an attachment on a companion, trail or aura.
- Category to slot: `top` <-> `torso`, `shoulder_companion` <-> `shoulder`, `nametag` <-> `name_tag`, the rest by name.

This refines spec ADR 0007's `{ "format": "rustic/1", "horizon": ..., "rustic": ... }` wrapper (ADR 0060 says why).
